# BYOA 구동 실험 (byoa-drive-probe)

차량 에이전트 허브 기획안의 대표 시연이 실제로 도는지 확인하는 최소 앱이다.
확인할 흐름은 하나다.

> **이벤트 수신 → 외부 읽기 → 음성 출력 → 내비 안내 시 중단·복귀**

시연용 앱이 아니다. 실험 결과를 기획서의 "지원 확인" 칸에 채우는 것이 목적이다.

## 구성

| 경로 | 내용 | Pleos SDK 의존 |
| --- | --- | --- |
| `core/` | 중단·복귀 게이트, 분량 규칙, 권한 게이트, 커넥터, 실험 기록 | 없음 (PC에서 테스트) |
| `app/` | 실험 화면, TTS 연결부, 내비 이벤트 연결부, 오디오 포커스 탐침 | TextToSpeech 3.3.1, NaviHelper 3.0.5 |
| `tools/mock_agent.py` | '내 에이전트' 역할의 웹훅 서버 (파이썬 표준 라이브러리) | 없음 |

핵심 원칙은 코드에 그대로 들어가 있다.
- 주행 상태를 모르면(`UNKNOWN`) 주행 중으로 간주한다 → 최소 화면만 표시
- 내비 우선순위가 검증되지 않았으면 자동 발화는 보류(`HELD`)하고, 운전자가 눌러야 재생
- 외부 에이전트는 읽기 전용. 허용한 컨텍스트 항목만 전달하고, 문장만 받아 읽는다
- 내비 안내가 끼어들면 읽던 문장을 멈추고, 안내가 끝나면 그 문장부터 다시 읽는다

## 준비 (E0)

1. Pleos Playground에서 **My Project 생성 → SDK 사용 신청** (TextToSpeech, NaviHelper)
2. Android Studio에 **Pleos Connect Emulator v2.1.0** 설치, AVD 생성, **Virtual Console** 설정, **마이크 접근** 설정
3. 이 폴더를 Android Studio로 연다. Gradle 동기화 시 Pleos Maven 저장소에서 SDK를 받는다
4. PC에서 핵심 로직 테스트: `./gradlew :core:test` → 전부 통과해야 한다
5. 앱을 에뮬레이터에 설치하고 실행

빌드가 실패하면 먼저 볼 곳:
- `PleosTtsSpeaker.kt`의 `EventListener` import 경로 (문서 예제에 없어 추정값). Alt+Enter로 고친다
- NaviHelper 권한: 문서의 Declaring permissions 표를 보고 `AndroidManifest.xml`에 추가

## 실험 체크리스트

각 실험이 끝나면 앱의 **기록 저장**을 누르고 파일을 받는다.

```
adb shell run-as ai.byoa.probe ls files
adb shell run-as ai.byoa.probe cat files/probe-log-<시각>.txt > probe-log.txt
```

저장 파일 끝에 **지연 요약**이 자동으로 붙는다.

### E1. TTS 기본 출력

- [ ] 앱 실행 시 기록에 `tts.init.ok`가 찍힌다 (실패하면 `tts.init.fail` 원인 기록)
- [ ] **세션 시작**을 누르면 모의 일정 브리핑이 한국어로 나온다
- [ ] 문장마다 `tts.request → tts.started → tts.done` 순서로 찍힌다
- [ ] 한국어가 아니면 TTS `setLocale()` 문서를 보고 로케일 설정을 추가한다

기록할 값: 외부 읽기 완료 → 첫 음성 시작 지연(ms)

### E2. 외부 읽기와 권한 게이트

1. PC에서 `python3 tools/mock_agent.py` 실행
2. 앱에서 **에이전트 교체** → "내 에이전트"로 바꾼 뒤 **세션 시작**

- [ ] 에뮬레이터에서 `http://10.0.2.2:8080/brief`로 요청이 들어온다 (PC 터미널에 `[요청]` 로그)
- [ ] 요청 본문에 `remain_minutes`, `driving_state`만 있고 `destination`은 **없다**
- [ ] `python3 tools/mock_agent.py --delay 6`으로 다시 실행 → 약 4초 뒤 "연결하지 못했습니다"를 읽는다
- [ ] 두 에이전트 모두 남은 시간 35분 / 12분 / 3분에서 읽는 문장 수가 6 / 2 / 1개로 같다 (**남은 시간 바꾸기**)

기록할 값: 세션 시작 → 외부 읽기 완료 지연(ms)

### E3. 내비 이벤트를 받을 수 있는가 (가장 중요)

이 실험 결과가 기획서 7장 "구동 실험 필요" 칸을 채운다.

**3-a. NaviHelper 연결**
- [ ] `PleosNaviSource.kt`의 주석 코드를 실제 시그니처로 채운다 (Android Studio 자동 완성으로 확인)
- [ ] Virtual Console로 경로 안내를 시작했을 때 남은 시간이 `navi.remain`으로 들어온다
- [ ] `remainTime` 단위(초/분)를 확인해 적는다
- [ ] 음성 안내가 나오는 순간을 알려주는 콜백이 있는지 확인한다 (있으면 그것을 `onGuidanceStarted/Ended`에 연결)

**3-b. 오디오 포커스 탐침** (3-a에 안내 콜백이 없을 때)
- [ ] **포커스 탐침**을 "관찰"로 둔다 (기록만 하고 브리핑은 멈추지 않음)
- [ ] 브리핑만 재생했을 때 `focus.change`가 찍히는지 본다 → 찍히면 **우리 TTS가 포커스를 뺏는 것**이므로 이 경로는 쓸 수 없다
- [ ] 내비 음성 안내가 나올 때 `focus.change LOSS_TRANSIENT`, 끝날 때 `GAIN`이 찍히는지 본다
- [ ] 위 두 조건이 맞을 때만 "연동"으로 바꿔 E4를 진행한다

결론 적기: 내비 안내 감지 경로 = NaviHelper 콜백 / 오디오 포커스 / 감지 불가 중 하나

### E4. 중단·복귀

먼저 **수동 버튼**(내비 안내 시작/종료)으로 로직을 확인하고, E3에서 찾은 실제 경로로 다시 한다.

- [ ] 브리핑 중 안내 시작 → 즉시 멈추고 화면이 "내비 안내 시 일시정지"로 바뀐다
- [ ] 안내 종료 → 멈췄던 문장의 처음부터 다시 읽는다
- [ ] 안내 중에 세션을 시작하면 안내가 끝날 때까지 기다렸다가 읽는다
- [ ] 같은 시험을 두 에이전트로 반복해 같은 동작인지 확인한다 (BYOA 장면)
- [ ] 기록에 `tts.done.ignored`가 찍히는지 본다 → 찍히면 SDK가 `stop()` 뒤에도 완료 신호를 보낸다는 뜻 (게이트가 무시하도록 처리돼 있음)
- [ ] 초기화 전에 세션을 눌렀을 때 `tts.not.ready`·`tts.fail`이 찍히고 화면이 멈추지 않는다

기록할 값: 안내 시작 → TTS 정지 확인(ms), 안내 종료 → 음성 재개(ms)
판정 기준(제안값): 정지 300ms 이내. 넘으면 기획서의 "검증된 재생 조건"을 더 좁힌다

### E5. 자동 발화 (선제 발화) 가능 여부

- [ ] **우선순위 검증 표시**가 꺼진 상태에서 **자동 트리거 흉내** → `gate.held`, 화면에 "자동 발화 보류됨"
- [ ] **보류된 브리핑 듣기**를 누르면 그때 재생된다
- [ ] 앱을 홈으로 내린(백그라운드) 상태에서 TTS 재생이 되는지 확인한다 (현재 코드는 화면이 떠 있을 때만 동작. 백그라운드 실험은 별도 Service가 필요하면 그때 추가)

결론 적기: 자동 호출 가능 / 앱 실행 중에만 가능 / 불가 → 기획서 8장 리텐션 가설의 전제

### E6. 주행 상태 불명

- [ ] 앱 시작 상태가 `UNKNOWN`이고 운전자 화면이 최소 화면이다
- [ ] **주행 상태 바꾸기**로 `PARKED`일 때만 남은 시간·읽지 않은 문장 수가 보인다
- [ ] (후속) AAOS Car API로 기어·차속을 받으면 `drivingState`에 연결한다. 받지 못하면 `UNKNOWN` 유지

## 이 코드에서 아직 확인하지 않은 것

- `EventListener` import 경로, NaviHelper 생성자·콜백 시그니처와 권한 이름 (문서 페이지에서 표가 보이지 않음)
- TTS 기본 로케일
- 백그라운드에서 TTS 재생이 허용되는지
- 이 작업 환경에서는 Pleos 저장소 접근이 막혀 앱을 빌드하지 못했다. 첫 빌드에서 나오는 오류는 위 항목부터 본다
